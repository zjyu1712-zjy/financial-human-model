# 生活开销与储蓄分配研究进展

更新日期：2026 年 11 月 26 日。

当前方向是根据个人可用资金、需要维持的生活和各方面的优先级，帮助用户比较生活开销与储蓄的分配方案。本阶段已明确输出维度、目标取舍原则和数据获取思路，八个输入方向均已形成首轮研究设计文档，分别说明数据、作用路径、依据和待确认事项。

本文汇总已确认的项目设计与候选研究方向。相应预算功能尚未写入现有原型；测量、机制和真实使用效果的证据状态见后文。

## 一 定位与研究范围

项目定位为个人辅助决策系统，按创业训练方向准备，以具体需求和产品用途推进。原始问题关注一个人希望维持的生活与支持这种生活的能力、资源之间的关系；当前将其落实为可量化的生活预算与储蓄比较。

长远面向有相关需求的成年人，首发人群尚未选定。大学生等群体是候选，后续根据决策任务、数据可得性和真实需求选择。产品形态仍开放；手环属于早期设想，当前没有确定硬件路线。

本轮重点是输入研究和必要的输出依赖梳理。需要分别讲清：每项数据是什么、怎样取得、为什么值得测，以及它通过什么核算规则、约束或待验证机制影响结果。

## 二 已确认的量化输出方向

在用户指定的规划期间内，先保障基本生活与已确定付款，再比较各生活板块和储蓄之间的资金分配。规划期间需要与收入、付款和目标期限对应，尚未统一限定为一个月或某个固定周期。

| 输出内容 | 表达方式与用途 |
| --- | --- |
| 各板块的开销安排 | 元／指定期间；有可靠参照时，列出比当前安排增加或减少多少 |
| 具体调整 | 减少、替换或延期哪些项目，对应金额及生活安排的改变 |
| 存钱进度 | 本期间可新增积累多少、与目标还差多少；在给定未来收支假设下比较期限变化 |
| 底线与资金缺口 | 哪项付款或生活底线受到影响，缺少多少资金；有日期资料时识别相应时点 |
| 方案取舍 | 哪些生活安排被保留、哪些被调整，以及储蓄进度如何变化 |

上述输出是已确认的设计方向。具体方案生成、排序及不确定性呈现方式仍待细化。

“存多少钱”需注明口径：本期向目标转入的金额、本期收支形成的净储蓄和期初已有积累分别展示。旧现金改为目标用途可以推进该目标，但不等于创造了同额新财富，详见[金融资源的存钱口径](./financial-resource-spec.md)。

### 生活板块

已纳入讨论的板块为：饮食、日常用品、住房与水电、娱乐、学习、交通、通信网络、衣物、医疗、保险、家庭支持、债务付款。后续可按场景调整；用户只需处理自己实际涉及的项目。

储蓄作为单独的资金去向，与消费开销分开展示。类别用于整理记录，同一类别内部还需区分已确定付款、最低安排和希望保留的安排。

### 两个目标如何并存

已确认采用“底线优先、两个目标并列、可调整范围由用户确认”的结构。

先检查已确定付款义务与最低可接受生活安排。满足这些条件后，同时比较期望生活和存钱目标。资金不足时，在用户可接受的范围内提供三类取舍：

1. **保留存钱进度**：维持目标进度，说明哪些生活安排需要调整、各减少多少钱。
2. **保留期望生活**：保留希望维持的安排，显示能够积累多少、目标期限怎样变化。
3. **双方适度调整**：保留更重视的安排，同时调整部分开销和储蓄进度。

三类方案须分别检查可行性。若某个目标无法在允许范围内实现，就显示缺口和需要重新确认的条件；“双方适度调整”也由用户的优先级和接受范围决定，不预设统一折中比例。

## 三 八个输入方向的首轮研究设计

原来的六个方向，加上时间资源与外部生活环境，均已有独立研究文档。这里的“方向”不是八项已验证量表，也不是要求用户一次填完的八组问题；具体字段是否纳入产品，仍取决于场景、数据可得性和实际帮助。

| --- | --- | --- |
| [情绪](./emotion-module-spec.md) | 账单线索初筛后，由用户区分认可的安抚支出、后悔多花和回避费用；用于预算内缓冲、未来可避免费用清单及系统内软承诺提醒 | 初筛与回忆误差、缓冲规则、提醒采纳和实际增量价值待测；四情绪不作每日必填，HR／RMSSD／SCL 估计焦虑路线已在本版本停止 |
| [健康](./health-spec.md) | 确认健康相关费用、保障与已有应急金；共享睡眠记录，按需确认疲劳体验和具体饮食／身体限制，检查替代活动能否执行 | 体验题项、提示条件、设备接口、保障充足判据与报销时点待细化；不生成健康总分或收入系数 |

| [时间资源](./time-resource-spec.md) | 按规划期和四类时段核对余量、分日类型睡眠底线与方案净新增耗时，筛选可执行的省钱安排 | 连续时段、轮班跨夜、杂务与休息留白、导入误差和实际耗时待核查；不把时间乘工资换成钱 |

## 四 已梳理的资金与生活安排输入

以下是计算所需的信息结构，不是让用户重新填写的整套表单。记录能回答的先复用；需要用户表达的目标与偏好，再请用户确认。

| 输入 | 当前明确的内容 | 影响什么 |
| --- | --- | --- |
| 期初资金 | 对应日期、已有金额、可动用部分及指定用途 | 确定分配起点，区分自由资金与已有用途的资金 |
| 收入 | 来源、金额、到账日期，已确认与预计分别标记 | 确定期间资金流入，识别先付款后到账的情况 |
| 当前开销 | 对应期间、板块金额与主要项目，保留记录或估计来源 | 提供调整前参照，说明“比现在改变多少” |
| 已确定的付款义务 | 金额、日期、用途，以及能否改变、改变条件 | 确定需要预留的资金和付款时点 |
| 最低可接受生活安排 | 必须保留的具体条件及对应费用 | 判断方案是否满足生活底线 |
| 期望安排及优先级 | 希望保留的项目、数量或频次，以及相对重要性 | 比较减少哪些安排带来的取舍 |
| 存钱目标 | 目标金额、期限、已有积累，金额和期限可否调整 | 比较新增积累、目标差额与进度 |
| 可接受的调整范围 | 哪些项目可以减少、替换或延期，以及可接受程度 | 把板块金额变化落实到具体行动 |

[金融资源](./financial-resource-spec.md)已细化资金分组、收入确定性、付款时点与信用消费口径；[生活品质要求](./lifestyle-requirements-spec.md)已细化最低安排、期望、目标与调整范围。取得方式仍是设计，完整账本与跨模块案例尚需核对。

### 已确定的付款义务

优先从已有账单、合同或其他付款记录提取用途、金额与日期，让用户确认遗漏、变化及可调整条件。历史上出现过的消费不能自动视为今后必须支付。

已确定付款与生活底线可以指向同一个项目。例如，同一期间的房租既是已确定付款，也用于满足居住条件，计算时只计入一次。

### 最低可接受生活安排

将“最低”落在具体生活条件上，再落实费用，而不是直接给各板块一个统一百分比。它表达的是用户确认的最低可接受安排；用户现在实际花了多少，只作为确认时的参照。

优先展示已有项目，让用户确认哪些必须保留、哪些还可以改变。只有无法判断某项安排所需费用时，再询问必要细节。费用未知时保留待确认状态。

### 期望安排及优先级

最低安排决定方案是否可接受；期望安排决定在可行范围内更想保留什么。用项目、频次或数量、费用表达期望，再确认相对重要性。

已有记录可生成待确认的生活安排，但过去的消费不自动代表未来偏好。资金不足时，围绕允许调整且优先级较低的项目进一步询问；不能仅凭优先级就假设某项一定能削减，或者削减后一定没有其他代价。

### 存钱目标

保持目标定义简洁：想累计到多少、希望什么时候达到、已经为该目标留下多少，以及金额或期限能否调整。目标总额与还需新增的金额分别显示；已有积累需要核对用途。

已经计入期初资金的目标积累仍是同一笔钱。为目标预留会改变可自由分配部分，不增加总资金，也不能再次算作本期间新增储蓄。同一笔积累不能完整地同时分配给多个目标。

### 可接受的调整范围

先有粗预算，只有某个项目确实需要调整时，再问能否减少、替换或延期。建议要同时表达具体改变和金额变化。延期付款只是改变支付时间；如果义务仍在，不把全部延期金额当成永久节省。

## 五 降低填写负担的获取方式

### 按记录情况进入

| 用户情况 | 已确认的使用路径 |
| --- | --- |
| 已有账单或记账记录 | 优先复用过去记录，核对分类不明、遗漏和异常项，无需重新记录一个月 |
| 没有记录，愿意先积累 | 边记录边看汇总；覆盖一个完整收支周期后，再进一步比较分配方案 |
| 没有记录，但现在就需要比较 | 使用已确认信息与注明范围的估计做条件比较，随后用实际记录修正 |

一个月可以作为准备期参考，是否足以比较取决于关键资料的覆盖。年度保险、季度付款或异常消费需要单独核对。可用资金、必须付款等关键项未知时，先汇总与提示待补项，不输出确定的可分配金额。

### 让用户确认而非重复填写

- **记录能回答的先复用**：从用户提供的账单或汇总整理历史开销、到账与付款信息；具体导入渠道和识别质量待核查。
- **记录无法回答的再确认**：可动用性、未来变化、存钱目标、生活底线和偏好由用户确认。
- **涉及调整时再问细节**：先形成粗预算，再围绕需要改变的项目补问；不要求一开始拆解全部生活。
- **未知与没有分别保存**：“暂时不知道”不能当作零；估计范围、来源与期间需要保留。

无记录用户也可研究定期汇总账单、补记现金支出等方式，不默认要求每天逐笔重填。数据来源的选择以测量对象是否合适、资料是否可得为依据；感受、目标与偏好采用适合的自我报告，设备记录不自动优于自我报告。

### 时间与环境按需获取

时间方面，拟复用日历、课表或排班，也可评估截图识别。导入后核对适用期间、误识别与遗漏。日历空白不等于可自由使用；仅在具体方案需要时确认能否腾出相应时段，不强制授权全部日历。

环境方面，用户可选择常住区域、学校或工作区域；也可经授权定位后确认实际生活区域。系统拟查询附近设施、路线与公开收费，用户确认优惠资格、实际可达性、厨房或食堂等使用条件。不要求持续定位。

具体规则见[时间资源](./time-resource-spec.md)与[外部生活环境](./external-environment-spec.md)。时间已细化到四类时段和方案净新增耗时；环境保留无接口、不授权或离线时的简短条件确认路径。接口、覆盖、准确度、授权及用户核对负担仍需评估，尚未接入程序。

## 六 核算口径与重复计算

以下口径用于后续例子核对与实现验收：

1. **同一笔开销只计算一次**：付款义务、生活底线和期望安排可以描述同一项目，不能把三份描述直接相加。
2. **资金余额与期间一致**：区分期初已有资金、本期间收入、本期间已支付与尚待支付，避免把已经从余额扣除的付款再扣一遍。
3. **已有储蓄与新增储蓄分开**：目标预留从同一资金账本划分用途，内部转账不产生新的收入或储蓄能力。
4. **按本人承担部分核算**：共同付款与家庭支持需确认实际承担额及条件，不能自动将完整账单都归入个人。本人先垫付再收回时，另保留全额付款和返还日期；不能用最终净份额替代付款日现金流。
5. **按同一期间比较方案**：目标金额、收入、开销及低频付款统一对应期间，并保留实际付款日期；月均可负担不自动表示付款当天资金足够。

这些口径形成了设计要求，尚需结合目标账本、来源数据和完整情景验证。

## 七 输入到输出的连接研究

八份设计已梳理出以下连接，整合时需要共用同一账本与方案记录：

- **金额与日期核算**：金融资源确定可动用资金和付款边界；关系中的本人份额、健康费用及信用费用进入同一记录，不另加一套收支。
- **偏好与调整边界**：最低安排、期望优先级、存钱目标、共同决定事项和允许改变的范围，限定哪些取舍可以提出。
- **执行条件筛选**：时间、健康与环境检查具体替代安排能否执行。用户选择后，金额变化来自该安排的实际费用差，不来自状态分数乘系数。
- **预算与决策支持**：情绪设计通过用户确认的消费经历，讨论预算内缓冲、避免后续费用及提醒；认知设计提供预测差额、费用解释与逐层呈现。提醒或展示本身不增加可用资金，历史已付费用也不能直接变成可回收的钱。

各文档已分别列出定义、获取方式、作用路径与文献支持范围。下一步需要核对跨模块的同一笔钱、同一段时间和同一条偏好是否重复或冲突，并验证这些信息是否比已有账本增加决策价值。情绪文档早期的每周时间总量校验，已由[时间资源规范](./time-resource-spec.md)细化；健康与时间复用睡眠记录，只扣一次。

当前设计不采用统一心理总分，也未完成效用权重或优化算法。原型中的 0–100 分及默认系数不能作为新方向已经校准的参数。现有文献支持范围沿用[候选表中的证据分类](./candidate-indicators.md)：理论支持、测量证据、预测关联或因果效应，需要与代码实现、本项目验证分别说明；各文档中的组合模型名称是项目设计描述，不代表已复现或验证了同名成品算法。
