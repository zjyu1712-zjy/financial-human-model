# 金融资源指标：测量、资金分配机制与设计规则

版本：研究设计基线 v1.0（草案）· 2026-11-25

本文归档“金融学人项目研究交接”对话中的金融资源设计，并区分已有研究依据与本项目拟采用的规则。相应资金分配功能尚未开发，也未开展真实用户验证。

## 1. 这个指标为什么需要

金融资源用于回答三件事：

1. 现有资金与本期收入，能否同时支持最低生活安排、期望开销和存钱目标；不能时差多少。
2. 钱能否在付款日前到位。整期收支相抵，不代表每个付款日都付得出。
3. 当前安排会动用多少已有资金、预留多少未来付款、向目标转入多少资金，以及留下什么后续付款责任。

它决定的是预算可行范围与付款条件。生活品质要求进一步决定在这个范围里保留什么、调整什么；时间资源用于检查调整能否执行。

主输出仍是：**在用户确定的收支周期内，各生活板块花多少钱、存多少钱，以及怎样调整。**

## 2. 测什么，怎样减少填写

金额以元计，均保留余额日期或收支日期，并对应同一规划期。优先复用用户提供的余额、账单和约定记录，只请用户确认记录不能回答的用途、可动用性与未来变化。截图识别和账单导入是拟评估的获取方式，不是已接通的功能。

| 内容 | 记录或确认什么 | 为什么需要；不测会少什么 |
| --- | --- | --- |
| 期初资金 | 本人可动用金额、已有指定用途、暂不纳入分配的资产、代管款；余额日期 | 确定分配起点。只看账户总额会把已有用途或不属于本人的钱也分出去 |
| 收入及到账日期 | 金额、日期、来源，分别标记已确认和预计收入 | 区分付款日前可用的钱与尚未落实的钱；只记月收入会漏掉时间缺口 |
| 已确定付款 | 本人应付金额、付款日、用途、现有预留，以及改变付款条件是否已获确认 | 识别必须支付的款项；历史消费本身不等于未来义务 |
| 低频付款 | 季度、年度或其他已知付款及现有预留；是否愿意提前分期留钱 | 避免只看一个月而漏掉大额低频支出；未选择预留不等于付款责任消失 |
| 信用消费与待还账单 | 交易所属板块、欠款、还款日、已留还款资金 | 区分消费发生与现金偿还，避免把信用额度当现金或重复记消费 |
| 日常开销参照 | 历史期间及各板块金额；异常月份、未来变化由用户核对 | 提供调整前参照，并为付款日之间的资金轨迹作初步估计 |

不要求逐笔重填已有交易，也不要求为未来每顿饭填日期。共同账单只计用户承担部分；未知金额、日期与“没有这项”分别保存。来源、估计范围及适用期间随数据保留。

期初可用资金、关键收入或必须付款等资料缺失时，先提示待补项；允许在注明假设的条件下比较，不输出确定的“还可以分配多少”。

无记录时沿用三条路径：先积累一个完整收支周期；直接使用注明来源的粗估；或先做汇总、补齐关键资料后再比较。已有记录不必重新记一个月。记录期还需检查是否遗漏年度或季度付款。

## 3. 当前核算设计

### 3.1 期初资金分组

| 分组 | 在预算中的处理 |
| --- | --- |
| 可自由安排的现金 `C_free,0` | 纳入本期自由分配起点 |
| 已有用途的现金 `C_earmarked,0` | 按目标储蓄、应急预留、已知付款预留分别记账；不再作为自由资金分配 |
| 暂不纳入本期分配的资产 | 如尚未确认是否变现、到账时间和可用金额的证券或存款；不默认加入现金预算 |
| 非本人可独立支配的资金 | 代管款排除；共同资金先确认本人可动用份额和条件 |

这里按本期可动用性分组，不是断言某种资产天然不能变现。现有预留若要改用途，需要用户确认并重算对应目标或付款缺口；不能只增加自由余额而保留原用途的足额状态。

### 3.2 已确认收入与预计收入分开

基础方案使用期初自由资金与已确认收入，并按预计到账日检查可用性。即使收入已经确认，到账前也不能用于更早的付款。

奖金、临时接单或其他金额、到账尚未落实的收入另作条件情景，例如“若这笔收入按时到账，可增加多少分配空间”。不凭空给收入乘一个统一概率系数。这里的“已确认”是记录状态，不是对未来到账的保证；发生延迟时需要重算。

### 3.3 低频付款和预留分开记

- 尚未到期：列出未来付款，用户可选择本期预留多少。这部分是指定用途的资金，不同时计为自由存钱目标的进度。
- 本期到期：从已有对应预留支付，其余未覆盖部分才占用自由资金。
- 同一笔钱从自由资金转为预留，是用途调整，不是消费，也不产生新收入；实际付款才减少总现金。

### 3.4 信用消费保留两种记录

消费记录回答“哪个板块用了多少钱”；现金记录回答“哪天真正付出多少钱”。两者不可混为一笔重复支出。

- 信用额度不计入现金资源。
- 以前期间发生、本期到期的账单，计入本期付款责任，不再算成本期新消费。
- 本期新增信用消费计入相应板块，同时拟在预算内预留还款资金；资金不足时显示未覆盖责任。
- 以后还款仍是实际现金流出，但从对应预留支付，不再次记成一笔新消费。

“预留”指预算中的用途记录，不表示产品已经冻结或划转银行账户资金。

两种记录对照时，同一笔新增信用消费及其还款预留只能对应一份资金需求：生活板块已经计入消费金额，就不能再把对应预留加成另一笔消费或额外预算用途。

### 3.5 历史开销只作参照与估计

复用日常开销记录，在已知大额收支节点之间暂按均匀发生估计日常现金支出。这是草案的简化假设，不能当成实际逐日消费预测。若用户知道某笔集中支出的日期，就应按该日期处理，不能再包含在均匀估计中重复扣除。

## 4. 输入怎样传递到输出

**资金可动用性与收入确定性 → 本期可分配范围；到账日与付款日 → 期间缺口；再结合生活底线、偏好和可执行调整 → 板块预算、计划存入金额与后续责任。**

对话把这套组合设计称为“双层流动性约束 + 关键节点逐日现金轨迹”：分别看已确认和预计收入情景，再检查规划期内的钱能否按时支付。这是本项目对核算方式的描述，不是一篇论文中已经验证过的同名成品模型。

### 4.1 整期核算与日期检查要同时做

先按自由资金口径检查规划期总额能否覆盖付款、生活开销、拟新增预留和目标存入，再检查日期。这里只计尚未由已有预留覆盖的部分，且同一笔消费与对应还款预留去重。简化轨迹为：

```text
C_assured(d) = C_free,0
             + 截至 d 日已到账的基础方案收入
             − 截至 d 日需要自由资金承担的付款
             − 截至 d 日估计发生的日常现金支出
```

该式只说明日期机制：`C_assured(d)` 是情景下的自由资金轨迹，不是账户总余额，也不是保证余额。已有预留承担的付款不再从自由资金扣；本期新预留、信用消费对应的还款预留、预留释放及目标转入，还需按各自日期记入完整账本。上述简式不能直接充当完整实现公式。

拟输出最低自由余额及日期、需要补足的金额，以及预计收入按时到账后的条件变化。均匀支出假设和未知付款会影响最低点；同日先付款后到账的问题，单靠日粒度也不能保证识别。

### 4.2 “存多少钱”要区分存量和流量

- 已为目标留下的钱是期初积累，不重复算作本期新增积累。
- 本期从自由现金转入目标的钱，增加该目标的已备资金；若来自以前已拥有的现金，只是用途重分配，不能说创造了同额新财富。
- 本期收入减去本期消费形成的净储蓄，与向某个目标转入的钱不是同一个口径；展示时需注明。

本文案例中的“计划存入”指本期拟向目标新增划分的金额。目标进度中已有积累只计一次；具体账本实现还需把旧资金转用途与本期收支形成的新增积累分开。

## 5. 模型依据与支持范围

本节区分理论、实证观察与项目规则。金额守恒、预留转移和重复扣款检查属于账本核算；文献用于解释为什么流动性、收入不确定性及支出认知值得纳入，不为本项目指定统一比例或默认系数。

| 理论或研究 | 支持本项目关注什么 | 本项目另外作出的设计选择 |
| --- | --- | --- |
| Deaton（1991），流动性约束下的消费与储蓄 | 借款限制与收入不确定性影响消费和储蓄；未来可能有钱不等于现在可用 | 按实际付款日期检查余额是本项目核算规则，论文没有验证本产品的日粒度算法 |
| Kaplan、Violante 与 Weidner（2014），富裕的“手停口停”家庭 | 持有较多非流动资产，也可能缺少可随时使用的流动财富 | 支持区分资产与可用现金；“已有指定用途现金”不等同论文中的非流动资产分类 |
| Carroll（1997），缓冲储蓄模型 | 收入不确定性和当期消费偏好等条件可以产生缓冲储蓄行为 | 已确认/预计收入分层及预留金额是项目设定，不能从论文直接读出统一安全比例 |
| Olafsson 与 Pagel（2018），个人财务软件记录研究 | 用收支、余额和信用额度记录研究到账后的消费反应，提示时间维度值得观察 | 该研究并未把所有到账反应归因于流动性不足；不能拿它证明所有用户都有付款日缺口 |
| Soman 与 Cheema（2002），信用额度与消费决策实验 | 信用额度可被当作未来收入的信号，其可信度影响消费反应 | 信用额度不计现金、交易与还款分账是本项目核算设计，不是该文检验的干预 |
| Sussman 与 Alter（2012），非常规支出研究 | 人们可能低估非常规支出的合计，并对单笔非常规支出超支 | 支持检查容易遗漏的支出；不直接证明季度账单的具体预留方法有效 |
| Thaler（1999），心理账户框架 | 人们按用途和来源组织、评价资金，账户分类会影响选择 | 用途标签需要用户确认；标签不是法律或物理上的不可动用，也不保证分类越多越好 |

## 6. 虚构案例：整期够用，付款日仍不足

假设规划期为 11 月 1—30 日，期初列出的资产及代管款合计 18,000 元：自由现金 2,000 元、已有用途现金 10,000 元、暂不纳入分配的证券资产 5,000 元、代管款 1,000 元。其中已有用途现金包含房租预留 1,500 元。

- 11 月 15 日确认工资 6,000 元；11 月 25 日预计接单收入 1,200 元，仅放在另一个情景。
- 11 月 5 日房租 4,500 元，已有预留覆盖 1,500 元，自由资金还需承担 3,000 元。
- 11 月 10 日支付以前期间的信用账单 800 元。
- 本期日常现金开销 2,400 元，暂按每日 80 元估计。
- 另拟新增低频付款预留 1,000 元、向存钱目标转入 800 元。为演示日期缺口，本例明确假定这两笔在期末划分。

整期自由资金来源为 `2,000 + 6,000 = 8,000` 元；用途合计为 `3,000 + 800 + 2,400 + 1,000 + 800 = 8,000` 元。

| 检查时间 | 自由资金轨迹 | 含义 |
| --- | --- | --- |
| 11 月 5 日末 | `2,000 − 3,000 − 5 × 80 = −1,400` 元 | 按此付款和支出安排，需要提前补足 1,400 元 |
| 11 月 14 日末 | `2,000 − 3,000 − 800 − 14 × 80 = −2,920` 元 | 工资到账前，累计未覆盖需求扩大到 2,920 元 |
| 整期合计 | 收入与所列用途相等 | 只看整期总额会遗漏上述缺口 |

负数表示假设安排下未覆盖的资金需求，不是已实际发生的账户透支。预计 25 日到账的钱不能解决 5 日的付款。是否释放其他预留、改付款日期或调整开销，需要确认可调整条件，不能自动动用应急金。

## 7. 尚待确认与验证

| 内容 | 当前状态或下一项核查 |
| --- | --- |
| 期初分组、确定性分层、付款与消费分开 | 已形成研究草案；不是现有产品功能 |
| 完整账本衔接 | 待细化新增预留、信用还款预留、释放和目标转入的日期，核对自由资金与总现金能否对账 |
| 逐日轨迹 | 待检查均匀支出假设误差、同日先后顺序和不确定到账；不使用假设轨迹宣称保证可支付 |
| 存钱口径 | 实现时分开旧现金改用途、本期新增积累和目标进度，不把内部划分当收入 |
| 数据获取 | 导入覆盖、分类错误、重复交易、本人份额及用户确认负担尚未试测 |
| 真实帮助 | 未验证用户能否理解分组、发现日期缺口，或因此改善预算执行 |

下一步拟用虚构完整账本检查守恒和跨期结转，再用经授权的真实记录核查覆盖与填写负担。目前没有招募、真实试用或效果数据。
